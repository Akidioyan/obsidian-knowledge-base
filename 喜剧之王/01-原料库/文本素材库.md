# 文本素材库（核心库 · 文本优先）

> 2026-11-25 建立。用户判断：**核心素材库应以文本优先**；陈佩斯《吃面条》这类「太看是谁在表演」的作品不宜作素材依据。
> 本库取代「生活憋屈库」成为生成的主入口。[[三库]] 降级为机制与规则索引。

## 为什么要文本优先

1. **可复制性**：文本可批量生成、检索、版本化、按 ID 回流数据；视频不能。素材是文本，成片只是文本的一次渲染。
2. **与生产能力匹配**：AI 视频生成最不稳定的是微表情、肢体精度、节奏停顿；最稳定的是情境、物件关系、屏幕上的字。素材若依赖前者，写出来的分镜根本拍不出来。
3. **与实测判据同源**：L3 看「复述率」。能被复述的只能是文本结构，不会是某个表情。

## 准入判据：复述测试

> **把梗写成两句话发给朋友，不看任何画面、不描述表演，对方会不会笑、会不会转述给别人？**
> 会 → 进核心库。不会，必须补一句「你得看他那表情／那个节奏」→ 表演依赖型，**不进库**，只留作落点参考。

这条判据同时是 L0 的准入线和 L3 的验收线，避免生成层和实测层用两套标准。

## 三类文本（核心是 A）

| 类 | 形态 | 地位 |
|---|---|---|
| **A 结构文本** | 一句话困境 + 角色必然的误读 + 后果 | **核心资产**，全部笑点在文字里 |
| **B 画面文字** | 系统提示／群消息／字条／通知／小票／购物车 | AI 视频最稳的笑点载体：静音可读、跨语言只需换字、不依赖表演 |
| C 台词文本 | 对白、俏皮话 | 只作加分项，不进核心库（依赖语言与表演） |

**判据补充**：A 类去掉角色名字仍然成立才算合格——笑点在情境结构，不在「这个角色很怪」。

## 字段规范

```
T-ID | 类别 | 原始困境文本 | 他的误读 | 后果/回收 | 能否一句话复述 | 语料来源 | 状态
```
`语料来源` 必填：`真实语料` / `[自编示范]` / `作品改编并注明出处`。**`[自编示范]` 一律标为待替换。**

## C 类 · 明确不进库（表演依赖型，反例）

| 作品桥段 | 为什么不进 | 依据 |
|---|---|---|
| 陈佩斯《吃面条》一碗碗吃到打嗝 | 写成两句话只是「一个人吃撑了」，笑点全在陈佩斯的身体反应、节奏与逐级失控的表演；换个人演就不成立 | [[拆片档案]] §8 |
| 憨豆海滩换泳裤 | 笑点在逐条抽裤管的肢体精度与时长，文本复述几乎没有笑 | [[拆片档案]] §1 |
| 基顿《将军号》炮口下垂 | 笑点在真实特技的可信度与不剪辑的等待，文本讲出来只是个段子 | [[拆片档案]] §2 |
| 憨豆餐厅牛排 | 半文本半表演：情境可复述，但「一块块藏」的节奏靠演；只留情境，不留节奏 | [[拆片档案]] §1 |

> 这些作品仍可用于**理解机制**，但不能作为**素材来源**。参考成熟作品 ≠ 抄它的表现形式。

## 我现在还缺的（诚实清单）

| 缺口 | 性质 | 怎么补 |
|---|---|---|
| **真实语料** | 上面 15 条全是我自编的示范，没有一条来自真实生活 | 需要评论区、群聊、论坛、客服对话等一手文本；或用户授权我去采集 |
| **真实反馈** | 我所有「好不好笑」仍是自评——而我在 [[评分表]] 里写过「AI 自评不能当筛选器」 | 必须跑一次 L3，哪怕内部盲评 |
| **AI 视频生成的能力边界** | 哪些动作能稳定生成、角色一致性多难、几秒会崩，我没实测过 | 先出一张角色参考图 + 一条 15s 试片 |
| **投放侧基线** | 时长档、审核红线、素材衰减、CTR 基线全是假设 | 需要真实账户数据或小预算测试 |
| **节奏经验值** | 多少秒一个笑点、铺垫多长、密度上限，全靠猜 | 由成片实测累积，不靠理论推 |
| **失败样本** | 淘汰规则来自理论与自编批次，没有「发出去没人笑」的记录 | 每批淘汰稿全量保留并回填 |
| **地域／文化差异** | 哪些在国内有效、出海失效，无数据 | 分市场统计「笑／无反应／被冒犯」三分 |
| **对「不好笑」的感知** | 能力层面：我能判断结构是否成立，判断不了好不好笑 | 只能靠外部信号校准，不能靠读更多理论 |

最根本的一条：**我能写出结构自洽的梗，但没有能力判断它是否好笑**。这决定了这条流水线必须由真实反馈收口，不能由我收口。
